# PRD — POTI 서버

> 원본: Notion (PRD — POTI 서버)  
> 마지막 동기화: 2026-08-15 / 서버 자체 업데이트: 2026-08-15

---

## 1. 문제 정의

기존 아이돌 굿즈 분철은 표준화된 방법이 존재하지 않고, X(트위터)·번개장터·윗치폼 등 여러 커뮤니티와 중고거래 플랫폼에 흩어져 진행된다.
이로 인해 모집자와 참여자 모두 **불필요한 피로**를 겪는다.

- **모집자**: 분철 글을 여러 플랫폼에 반복 게시하고, 참여자의 입금·배송 상태를 개별 채팅으로 확인해야 함
- **참여자**: 원하는 굿즈의 분철 글을 찾기 어렵고, 진행 상황을 파악하려면 직접 문의해야 함

---

## 2. 솔루션

> 흩어진 분철 탐색·모집·거래 과정을 하나의 흐름으로 통합하여, 분철 진행 상태를 문의 없이 한눈에 관리할 수 있도록 돕는다.

채팅 없이도 **구조화된 상태 관리 UI**만으로 분철 전 과정을 진행할 수 있는 것이 포티의 핵심 전제다.

거래 과정에서 발생하는 대부분의 채팅은 새로운 의사결정을 위한 소통이 아니라, **현재 분철이 어디까지 진행되었는지를 확인하기 위한 문의**다. 포티는 이 문의를 상태 시각화로 대체한다.

---

## 3. 핵심 사용자

| 역할 | 설명 | 주요 Pain | 원하는 Gain |
|---|---|---|---|
| **모집자 (총대)** | 분철 글을 작성하고 공구를 주도 | 참여자 상태를 채팅으로 일일이 확인해야 함 | 참여자 상태를 한눈에 관리하고 싶음 |
| **참여자 (구매자)** | 분철 글에 참여하여 굿즈 구매 | 진행 상황을 파악하려면 직접 문의해야 함 | 별도 문의 없이 현재 상태를 스스로 파악하고 싶음 |

---

## 4. 핵심 가치 제안

| 구분 | 내용 |
|---|---|
| **Pain Reliever** | 분철 글만 선별하여 원하는 그룹의 분철 글을 한 곳에서 제공 → 불필요한 탐색 비용 감소 |
| **Pain Reliever** | 입금·배송 등 거래 상태를 단계별로 자동 표시 → 진행 상황 불확실성 해소 |
| **Gain Creator** | 최애 그룹 선택 기반 개인화 분철 굿즈 추천 제공 |
| **Gain Creator** | 단계별 거래 상태를 직관적으로 확인할 수 있는 UI |

## 5. 북극성 지표

> 🌠 **월간 분철 완료 건수**

사용자가 신뢰를 기반으로 분철에 참여하고 거래가 문제없이 종료되었음을 의미하므로 포티의 북극성 지표로 설정.

## 6. 핵심 가설

### H1 — 표준화된 등록 폼
> 표준화된 분철 등록 폼을 제공하면 모집자는 상품 등록을 더 쉽게 완료할 수 있으며, 분철 등록 완료율은 증가할 것이다.

- **채택 기준**: 등록 시작 모집자 중 완료율 60% 이상
- **기각 시**: 서비스 피봇 또는 다른 방향 확장 검토

### H2 — 채팅 없는 상태 관리 ← 포티의 핵심 가설
> 채팅 없이도 상태 변경 UI만으로 분철 진행 상황을 충분히 전달할 수 있으며, 이를 통해 모집자에게 오는 문의성 채팅이 감소할 것이다.

- **채택 기준**: 릴리즈 후 분철 진행 상황 관련 문의가 전체 문의의 20% 이하
- **채택 시**: 채팅 이외의 기능 고도화에 집중
- **기각 시**: 채팅 기능 우선 구현 및 대안 방안 고안

### H3 — 최애 기반 개인화 추천
> 선택한 최애 그룹을 기반으로 한 개인화 추천은 사용자의 탐색 시작률을 높이고, 홈 화면에서 추천 굿즈 클릭률을 증가시킬 것이다.

- **채택 기준**: 추천 굿즈 클릭률이 검색 경유 클릭률보다 1.3배 이상 높음
- **채택 시**: 알고리즘 고도화
- **기각 시**: 탐색 방식 자체를 재검토

## 8. 로드맵

### Phase 1 — 앱잼 (2025.12.21 ~ 2026.01.24)
**목표**: 핵심 플로우 구현 및 데모 완성

- **MUST**: 로그인, 등록, 분철팟, 분철팟 상세, 참여, 모집 내역, 참여 내역
- **SHOULD**: 온보딩, 최애 선택, 자동완성, 별점 리뷰, 마이페이지, 모집자 상세, 멤버 필터링
- **COULD**: 홈 굿즈 추천, 분철팟 정렬, 홈 배너

### Phase 2 — 릴리즈 전 (2026.01.25 ~ 2026.08)
**목표**: 가설 검증을 위한 MVP 완성 및 베타 테스트 준비

- **MUST**: 알림 (✅ 완료), Google/Apple 로그인 연동 (✅ 완료)
- **SHOULD**: 최애 수정 (✅ 완료)
- **완료**: ✅ 검색, ✅ 아티스트별 굿즈 리스트, ✅ 어드민 패널, ✅ 계좌번호 암호화, ✅ dev/prod 인프라 분리, ✅ 주소 관리, ✅ 타인 프로필, ✅ 내 계정 설정 조회, ✅ FCM AFTER_COMMIT 분리 (PR #258), ✅ Authorization 누락 예외 처리 (PR #257)
- **기타**: 가설 검증용 데이터 수집 대시보드 구축

### Phase 3 — 릴리즈 후 (2026.08~)
**목표**: 가설 결과 기반 피봇 또는 확장

- H2 채택 시: 상태 관리 UX 고도화 집중

- H3 채택 시: 개인화 추천 알고리즘 고도화
- 장기: 포토카드 외 다른 분야 분철로 서비스 확장

## 9. 설계 원칙

1. **채팅 없이 상태로 소통한다** — 거래 진행 상황 문의는 상태 UI로 대체. 채팅은 예외 상황 보조 수단.
2. **표준화된 폼으로 진입 장벽을 낮춘다** — 모집자가 별도 지식 없이도 분철을 등록할 수 있어야 한다.
3. **최애 기반으로 탐색을 개인화한다** — 사용자가 원하는 굿즈에 빠르게 도달할 수 있어야 한다.
4. **신뢰를 수치로 증명한다** — 별점 리뷰와 분철 완료 이력이 모집자 신뢰도를 가시화한다.

## 10. 마감일 초과 처리 정책 (2026.06.09 확정)

모집 마감일이 지났을 때 목표 수량 달성 여부에 따라 분기한다.

| 조건 | 처리 |
|------|------|
| 모집 수량 ≥ 목표의 50% (과반수 이상) | 모집자가 나머지 수량 부담, 분철 계속 진행 |
| 모집 수량 < 목표의 50% (과반수 미만) | 분철글 삭제, 모집자·참여자 전원 알림 발송 |

**알림 정책**
- 모집 마감 **1일 전**: 모집자에게 리마인더 알림 (이슈 #222)
- 입금 마감: 모집 완료(CLOSED 전환) 후 **24시간**
- 입금 마감 **3시간 전 / 30분 전**: WAIT_PAY 참여자에게 각 1회 알림 (이슈 #222)
  - 제목: `입금 마감까지 {남은시간} 남았어요 ⏰`
  - 내용: `{분철글명} 입금을 완료한 후 입금 완료 버튼을 눌러주세요`
- 과반수 미달 삭제 시: 모집자·참여자 전원에게 취소 알림 (이슈 #228)

**입금 미확인 주문 자동 취소 시 총대 처리 (2026.08.20 확정)**
- 입금 마감 내 미확인 주문은 자동 취소, 해당 수량은 **총대 부담**으로 처리 (CLOSED 유지)

## 13. 게스트 모드 정책 (2026.08.20 확정)

비로그인 유저가 딥링크·SNS 유입 시 서비스를 둘러볼 수 있도록 게스트 모드를 도입한다.

**허용 범위**

| 기능 | 게스트 허용 |
|------|------------|
| 홈 피드 조회 | ✅ (인기순 폴백) |
| 검색 | ✅ |
| 분철글 상세 조회 | ✅ |
| 아티스트 목록/상세 | ✅ |
| 참여 | ❌ 로그인 필수 |
| 분철 등록 | ❌ 로그인 필수 |
| 마이페이지 | ❌ 로그인 필수 |
| 입금·배송 | ❌ 로그인 필수 |

**홈 피드 폴백 정책**
- 비로그인 또는 최애 미설정 유저: 인기순 분철글 노출

**참여 시도 UX 흐름**
- 로그인 상태: 참여하기 → 정보 입력 → 완료
- 비로그인 상태: 참여하기 → 로그인 유도 모달 → 로그인 완료 → 기존 분철글로 복귀 → 참여 진행

**서버 처리**
- 공개 API는 JWT 없어도 접근 허용 (ADR-011 참고)
- 인증 필수 API는 기존과 동일하게 `40105` 반환, 로그인 유도는 클라이언트 처리
