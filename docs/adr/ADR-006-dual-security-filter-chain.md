# ADR-006: 이중 Spring Security 필터체인 (어드민 vs API)

**상태:** 채택됨  
**결정일:** 2026.07

---

## 컨텍스트

운영 단계에서 사용자 관리(정지·탈퇴)와 분철글 관리가 필요하다. 이를 위한 어드민 패널을 동일 서버에서 운영하기로 했다.

문제는 인증 방식이 다르다는 것이다.

- **어드민 패널**: 브라우저에서 ID/PW로 로그인하는 세션 기반 인증, 서버사이드 렌더링(Thymeleaf)
- **모바일 API**: JWT 토큰 기반 무상태 인증

두 방식을 하나의 인증 체계로 합치면 서로의 동작에 간섭이 생긴다.

---

## 결정

Spring Security FilterChain을 우선순위를 달리하여 두 개로 분리한다.

- **Order 1**: `/admin/**` 전용 — Form Login, 세션 기반, ADMIN 권한 필요
- **Order 2**: `/api/**` 전용 — JWT 필터, 무상태 세션, 화이트리스트 외 인증 필수

어드민 계정 정보는 코드에 하드코딩하지 않고 환경변수(`ADMIN_USERNAME`, `ADMIN_PASSWORD`)로 관리한다.

---

## 이유

- `securityMatcher`로 스코프를 명확히 분리하면 두 체인이 서로 간섭하지 않는다.
- 어드민 경로가 JWT 체인에 노출되거나, API 경로가 세션 체인에 걸리는 사고를 구조적으로 방지한다.
- 어드민 비밀번호를 환경변수로 관리하면 코드 변경 없이 비밀번호를 교체할 수 있다.

---

## 결과

- JWT API와 어드민 패널이 충돌 없이 동일 서버에서 운영된다.
- prod/dev 서버 환경변수에 `ADMIN_USERNAME`, `ADMIN_PASSWORD` 추가 필요.
- 어드민 패널 접근은 내부 네트워크 또는 VPN 제한을 추후 검토한다.
