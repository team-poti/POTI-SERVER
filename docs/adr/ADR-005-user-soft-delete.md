# ADR-005: User 소프트 삭제

**상태:** 채택됨  
**결정일:** 2026.01

---

## 컨텍스트

회원탈퇴 시 사용자 데이터를 물리적으로 삭제하면 두 가지 문제가 생긴다.

1. 해당 사용자가 참여했던 분철 내역, 리뷰 등 **다른 사용자의 거래 기록**에 결함이 생긴다.
2. 연관된 Order, Review, Payment 등 모든 엔티티를 cascade 삭제해야 하므로 구현이 복잡해진다.

포티는 신뢰 기반 거래 서비스이므로 거래 이력의 연속성이 중요하다.

---

## 결정

탈퇴 시 물리 삭제 대신 **식별 정보만 익명 처리**한다.

- 닉네임 → `"탈퇴한 사용자"`
- 이메일, 프로필 이미지 → 삭제
- socialId → 무작위 값으로 교체 (재가입 시 unique 충돌 방지)
- 탈퇴 사유·일시 기록

탈퇴 전 **진행 중인 거래(주문)가 있으면 탈퇴를 차단**한다.

---

## 이유

- 다른 사용자의 거래 기록(리뷰, 분철 내역)에 '탈퇴한 사용자'로 표시되어 UX가 유지된다.
- socialId를 무작위 값으로 교체하므로 같은 소셜 계정으로 재가입해도 unique 제약을 침범하지 않는다.
- 진행 중 거래 차단으로 분철 흐름이 끊기는 상황을 방지한다.

---

## 결과

- 탈퇴한 사용자의 과거 거래 기록은 '탈퇴한 사용자' 표시로 유지된다.
- 거래 완료 후에는 탈퇴 가능하므로 분철 신뢰도 보호.
- 어드민은 필요 시 강제 탈퇴 처리가 가능하다.
