# ADR-011: 게스트 모드 — 공개 API 선택적 JWT 인증

**상태:** 채택됨  
**결정일:** 2026.08

---

## 컨텍스트

딥링크로 비로그인 유저가 앱에 진입할 경우 현재는 로그인 화면으로 튕겨난다. 서비스 특성상 분철글 상세를 로그인 없이 미리 볼 수 있어야 딥링크가 의미를 가진다.

또한 웹/SNS를 통해 유입된 신규 유저가 로그인 전에 홈 피드와 검색으로 서비스를 둘러볼 수 있어야 한다.

기존 보안 설정(ADR-006)은 WHITE_LIST에 없는 모든 `/api/**` 경로에 JWT 인증을 강제하고 있어, 구조적인 변경이 필요하다.

---

## 결정

API를 세 등급으로 분류한다.

| 등급 | 설명 | 처리 방식 |
|------|------|-----------|
| **공개** | 로그인 없이 접근 가능 | `WHITE_LIST` 추가 → `permitAll()` |
| **선택적** | 비로그인도 허용하나 로그인 시 개인화 | JWT 있으면 파싱, 없으면 `null` 허용 (`@AuthenticationPrincipal` nullable) |
| **인증 필수** | 사용자 식별 필수 | 기존과 동일 — 토큰 없으면 40105 반환 |

**공개 API (WHITE_LIST 추가)**
- `GET /api/v1/home` — 홈 피드 (비로그인 시 인기순 폴백)
- `GET /api/v1/posts/**` — 분철글 상세 조회
- `GET /api/v1/feeds` — 피드 검색
- `GET /api/v1/search/**` — 검색
- `GET /api/v1/shippings` — 배송 옵션 조회
- `GET /api/v1/artists/**` — 아티스트 목록/상세

**인증 필수 유지**
- `POST /api/v1/orders` — 참여
- `POST /api/v1/posts` — 분철 등록
- `/api/v1/users/**` — 마이페이지
- 입금·배송 관련 전체

---

## 이유

- 공개 API는 `permitAll()`만으로 충분하다. JWT 파싱 자체를 건너뛰므로 구현이 단순하다.
- `@AuthenticationPrincipal`이 `null`인 경우를 핸들링하면 "비로그인 시 개인화 없음" 동작을 자연스럽게 구현할 수 있다.
- 화이트리스트 방식은 기존 ADR-006 구조를 유지하면서 최소한의 변경으로 게스트 모드를 도입할 수 있다.

---

## 결과

- 비로그인 유저가 홈·검색·분철글 상세에 접근 가능해진다.
- 홈 피드는 로그인 유저(최애 기반) / 비로그인 또는 최애 미설정 유저(인기순) 분기 로직 추가 필요.
- 참여·등록 시도 시 클라이언트에서 로그인 유도 모달 처리 (서버는 기존과 동일하게 40105 반환).
- 로그인 완료 후 기존에 보던 분철글로 복귀하는 딥링크 플로우는 클라이언트 처리.
