CLAUDE.md를 먼저 읽는다. 핵심 이슈(상태값 재정의, 미확정 항목)와 기술 스택을 파악한다.
git diff HEAD~1..HEAD 또는 최근 변경 범위를 보고 맥락을 잡는다.

아래 순서로 개선 기회를 찾는다.

1. 미완성 연동 (CLAUDE.md "핵심 이슈" 기준)
   - 변경된 코드가 미확정 상태 전환 조건과 맞닿아 있는가
   - GroupBuyPost ↔ Order 상태 자동 전환 로직 중 구현되지 않은 경로가 있는가

2. 테스트 갭
   - 추가된 비즈니스 로직(분기, 예외) 중 테스트가 없는 경로
   - 동시성(비관적 락, afterCommit) 관련 케이스

3. 쿼리 / 성능
   - N+1 가능성 (Lazy 로딩 + 루프)
   - 락 범위가 필요 이상으로 넓거나 좁은 부분

4. 기술 부채
   - TODO / FIXME / 임시 주석
   - ddl-auto: update 의존 중 스키마 변경 누락 가능성

5. 운영 안전성
   - 알림 실패가 본 로직을 깨는 경로
   - 로그에 개인정보(계좌·배송지·연락처) 노출 가능성
   - 설정값 하드코딩 (application.yml에 있어야 할 값이 코드에 있는 경우)

출력 형식: 카테고리별로 "파일:줄 / 문제 / 개선 방향" 한 줄씩.
확실하지 않은 것은 "확인 필요:" 접두어를 붙인다.
칭찬은 쓰지 않는다. 없으면 "개선 항목 없음"으로 끝낸다.
